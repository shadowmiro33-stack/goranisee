# UI 작업 기준 (랜딩·어드민 공통)

AI 티 나는 결과물을 피하기 위한 기준. 디자인은 감각보다 기준으로.

## 금지 (먼저 정하고 시작)
- 보라/파랑 그라데이션 히어로, 카드 나열 그리드, 둥근 모서리+그림자 일괄 적용, 이모지 섹션 마커, 전부 가운데 정렬
- Inter / Space Grotesk 같은 "무난한" 기본 서체만 쓰기
- 의미 없는 애니메이션(모든 요소 페이드인), 100vh 히어로로 첫 화면을 비우기

## 색
- 브랜드 색 **하나** + 회색조(브랜드 색 쪽으로 살짝 기운 회색). 상태색(성공/경고/위험)은 별도.
- 라이트·다크 둘 다 토큰으로 정의.

## 서체
- 제목용 1종(개성) + 본문용 1종(가독) 조합. 한글은 Pretendard 또는 IBM Plex Sans KR 계열로 본문 가독성 확보.
- 숫자는 tabular-nums, 본문 폭 65자 내외.

## 모션 (랜딩에서만, 목적이 있을 때)
- 배경: Three.js로 천천히 도는 3D 한 개(브랜드 소재와 연결될 때만, 예: 차량 실루엣·도로 라인). 성능 예산: 모바일에서 60fps, 15MB 이하.
- 스크롤: GSAP ScrollTrigger로 글자·선이 스크롤에 따라 드러나는 한 가지 장치. 여러 효과를 섞지 않음.
- `prefers-reduced-motion`이면 전부 끔.
- **어드민·도구 화면에는 적용하지 않음** (읽고 조작하는 화면은 정보 설계가 우선).

## 마무리 점검 (필수)
1. 폰(390px)·PC(1280px) 화면을 직접 스크린샷으로 찍어 본다.
2. 어색한 곳(잘린 텍스트, 빈 공간에 늘어난 카드, 겹침, 대비 부족)을 고친다.
3. 가능하면 Impeccable 스킬(디자인 점검)로 한 번 더 걸러낸다.

## 클로드에게 시키는 문장 (예)
"우리 서비스 랜딩페이지 새로 만들어줘. 보라 그라데이션·카드 나열 같은 AI 티 나는 건 빼고 색은 브랜드 색 하나만, 배경은 Three.js 3D, 스크롤 효과는 GSAP으로. 다 되면 폰·PC 화면 직접 찍어 보고 어색한 데 고치는 것까지."
